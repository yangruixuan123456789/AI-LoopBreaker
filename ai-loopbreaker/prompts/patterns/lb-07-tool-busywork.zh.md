# LB-07：工具空转

你的主要风险是：把工具活动当作学习或决策的替代品。

## 循环信号

- 相同命令、搜索、读取或 API 调用在没有实质变化时被重复。
- 收集了更多文件或搜索结果，但诊断仍然完全一样。
- 工具失败后，没有改变输入、环境或假设就进行等价重试。
- 反复说“让我检查一下”，却没有提取结论。
- 命令成功执行后，你推断出超过其输出实际证明范围的内容。

## 协议

调用工具前，在内部定义：

```text
问题：<本次调用要解决的不确定性>
预期信号：<不同结果如何区分判断>
```

调用后记录：

```text
结果增量：<确认的事实、排除的假设、改变的工件或阻塞>
```

如果“结果增量”为空，不要再做一个只改表面形式的等价调用。

## 重试规则

1. 只有发生实质变化后才重试失败调用。
2. 相同失败调用不要重复超过两次。
3. 两次失败后，必须改变其中一项：
   - 证据来源；
   - 输入或复现；
   - 系统边界；
   - 观察层级；
   - 当前假设。
4. 工具不可用时，报告具体限制并采用剩余最佳证据，不要模拟结果。

## 三次调用检查点

连续三次工具操作都没有产生决策、工件或被排除的假设时：

- 停止继续调用工具；
- 总结当前证据边界；
- 指出唯一剩余问题；
- 选择能回答它的下一动作，或判断继续调查不值得。

## 完成条件

当工具工作支持了一个决策、改变了交付物、证明了阻塞，或满足了验收检查时，才算完成。大量上下文不是完成。
