# 案例：阻止“只修一处”

**中文** | [English](fix-coverage.md)

## 报告的问题

```text
用户在分页列表点击“下一页”后，当前筛选条件会消失。
```

## 局部修复常见的做法

助手找到 `onNext` 处理器，把 `filters` 复制进它生成的请求。用户报告的点击路径暂时正常。

但分页还可以通过以下方式触发：

- 输入页码；
- 点击“上一页”；
- 浏览器前进/后退；
- 恢复已保存视图；
- 后台刷新。

这些路径仍然从不同的状态来源构造请求。第一个症状消失了，但业务不变量仍然是坏的。

## LoopBreaker 响应

```text
循环：LB-13 修复覆盖不全
重复：只修复了用户报告的“下一页”处理器，没有检查其他切换页码路径。
新证据：分页可以从五个不同入口触发。
根因未知：这些入口是否读取同一份规范筛选状态。
下一动作：梳理每个入口的请求构造过程，在最窄的共享边界执行不变量。
完成条件：所有导航方式产生等价的筛选参数。
需要决策：无。
```

## 关闭矩阵

```text
影响面          预期不变量               结果
下一页          保留当前筛选             通过
上一页          保留当前筛选             通过
直接输入页码    保留当前筛选             通过
浏览器历史      恢复并保留当前筛选       通过
恢复已保存视图  恢复并保留当前筛选       通过
后台刷新        保留当前筛选             通过
空筛选集合      一致地省略筛选参数       通过
```

## 为什么这不是范围扩大

修复既没有重构无关的分页代码，也没有增加新的筛选功能。它只是在所有可能违反同一不变量的路径上完成关闭。这属于有边界的完整性，不是开放式清理。
